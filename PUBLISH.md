# Публикация чистой копии проекта «Бит»

**Подготовленное имя нового репозитория:** `TVSrv/bit-t114`  
**Комплект исходников:** T114 `0.41-sync-test` + Android `0.19-test`.

Этот комплект собран из файлов одной версии. Он **не является форком** и **не содержит историю коммитов** старого приватного репозитория. Старые дизайн-материалы `bit-art/` и `previews/` не включены до подтверждения лицензий.

## Быстрый способ — GitHub CLI на ПК или в Termux

1. Скачайте и распакуйте `bit-t114-0.41-android-0.19-public-source.zip` в отдельную **новую** папку. Не распаковывайте в старую Git-копию.
2. Установите Git и GitHub CLI (`git` и `gh`), войдите в свою учётную запись через `gh auth login`.
3. Из каталога, где после распаковки находится `README.md`, выполните:

```bash
git init -b main
git add .
git commit -m "Initial public snapshot: Bit 0.41 + Android 0.19"
gh repo create TVSrv/bit-t114 --public --source=. --remote=origin --push
```

Перед выполнением команд проверьте, что в каталоге нет папки `.git`: `ls -a`. Если она есть, вы находитесь не в чистой распакованной копии — остановитесь.

Команда создаст **новый** публичный репозиторий `https://github.com/TVSrv/bit-t114` с единственным новым начальным коммитом. Старые ветки, теги и коммиты старого приватного проекта не переносятся.

## Через интерфейс GitHub

Откройте https://github.com/new, выберите имя **`bit-t114`**, видимость **Public**, затем создайте пустой репозиторий (без README, лицензии и .gitignore: эти файлы уже находятся в архиве).

После создания репозитория выполните в распакованном каталоге:

```bash
git init -b main
git add .
git commit -m "Initial public snapshot: Bit 0.41 + Android 0.19"
git remote add origin https://github.com/TVSrv/bit-t114.git
git push -u origin main
```

Вход в GitHub для `git push` выполняется через GitHub CLI, менеджер учётных данных или SSH; обычный пароль аккаунта для HTTPS push не подходит.

## После публикации

1. Откройте вкладку **Actions** нового репозитория и разрешите запуск workflow, если GitHub попросит подтверждение. `build.yml` собирает firmware/OTA и Android debug APK.
2. Укажите в разделе **About** описание и темы: `tamagotchi`, `heltec-t114`, `nrf52840`, `android`, `platformio`, `pixel-art`, `bluetooth-le`.
3. Перед первым релизом проверьте реальную T114 и Android. APK из CI подписан отладочным ключом, а не постоянным релизным.
4. Пройдите аудит прав на графику и сторонние компоненты: [ASSETS-LICENSE.md](ASSETS-LICENSE.md) и [контрольный список](docs/PUBLICATION_CHECKLIST.md).
5. Если собираетесь публиковать APK/OTA через Releases, добавьте контрольные суммы и отмечайте тестовый статус.

## Что делать нельзя

**Не используйте** `git clone` старого приватного репозитория с последующим `git push --mirror`, не выполняйте Fork или Import repository из него. Эти способы могут случайно открыть приватную историю и старые файлы.

Проверить отсутствие истории в новом репозитории можно через вкладку **Commits**: там должен быть один начальный коммит.

Если `gh repo create` сообщает, что репозиторий уже существует, проверьте имя и страницу GitHub; не переписывайте существующий репозиторий без явного решения владельца.
